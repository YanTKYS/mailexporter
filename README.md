# mailexporter

Outlook で選択したメールを、件名・差出人・宛先などのヘッダー情報付きPDFと添付ファイルとして自動保存する PowerShell スクリプトです。

`ProcessEml.ps1` 単体で完結し、Outlook・Microsoft Word・Windows PowerShell の標準機能のみで動作します（追加ランタイムのインストールは不要です）。

## できること

- Outlook で選択した1件、または複数のメールを一括処理
- 件名・差出人・宛先・CC・受信日時のヘッダーと、メール本文、添付ファイル一覧をまとめた指定様式のPDFを生成
- 添付ファイルをメールごとのフォルダにそのまま保存
- 件名に `[` `]` などファイル名として有効だが特殊な意味を持ちうる文字が含まれていても、ワイルドカードとして誤解釈せず安全に処理
- メールごとの保存フォルダに処理ログを自動生成し、途中でエラーが発生した場合も処理段階・例外内容・発生位置を記録

## 動作要件

- Windows
- Windows PowerShell 5.1（またはそれ以降の Windows PowerShell 系）
- Microsoft Outlook（デスクトップ版、起動済みであること）
- Microsoft Word（デスクトップ版、インストール済みであること。PDF変換に使用する）

## 使い方

1. Outlook を起動し、保存したいメールを1件または複数選択する
2. `ProcessEml.ps1` を実行する

   ```powershell
   powershell.exe -ExecutionPolicy Bypass -File .\ProcessEml.ps1
   ```

3. 選択した各メールについて、デスクトップに以下の内容のフォルダが作成される

   ```text
   Desktop
   └─ yyyyMMdd_<件名>
      ├─ yyyyMMdd_<差出人>mail.pdf     … ヘッダー付きメール本文のPDF
      ├─ 処理ログ_yyyyMMdd_HHmmss.txt  … そのメールの処理ログ
      └─ <添付ファイル名>              … メールの添付ファイル（複数可）
   ```

4. 処理完了後、保存先フォルダ（複数メール処理時はデスクトップ）が自動的に開く

同じ日付・件名のメールを重複して処理した場合は、既存フォルダを上書きせず `_2`、`_3` … という連番フォルダに保存される。

## ログ

- ログはメールごとの保存フォルダに `処理ログ_yyyyMMdd_HHmmss.txt` として作成される
- 各ログには、起動時の共通ログ（Word・Outlookの確認、選択メール件数）と、そのメール自身の処理内容が記録される
- 保存フォルダを作成できないまま失敗した場合は、デスクトップの `MailExporter_Error_yyyyMMdd_HHmmss.txt` にログを退避する
- ログファイルへの書き込みに失敗した場合でも、メール保存処理自体は継続し、以降はコンソール出力のみに切り替わる
- メール本文や添付ファイルの内容そのものはログに記録しない
- エラー発生時は、発生日時・処理対象メールの件名・処理段階・例外メッセージ・例外種別・スタックトレース・発生位置をログに残す
- 処理完了時、コンソールに成功件数・失敗件数（メール以外のアイテムを選択していた場合はスキップ件数）を表示する
- 複数メール処理中に一部のメールでエラーが発生しても、残りのメールの処理は継続する

## 設定

スクリプト冒頭の `$CONFIG` で主な挙動を変更できる。

| キー | 内容 | 既定値 |
| --- | --- | --- |
| `MaxSubjectLength` | フォルダ名に使う件名の最大文字数 | `200` |
| `MaxSenderLength` | PDFファイル名に使う差出人名の最大文字数 | `50` |
| `MaxPathLength` | 保存先パスの最大長（超過時は自動短縮） | `240` |
| `OpenFolderAfterProcess` | 処理完了後に保存先フォルダを自動で開くか | `$true` |
| `EnableLogging` | 処理ログをファイルに残すか（`$false` の場合はログファイルを作成しない） | `$true` |

## 注意事項

- 件名や差出人名に含まれる `\ / : * ? " < > \|` は、Windowsのファイル名で使用できないため全角文字に置換して保存される（`[` `]` はファイル名として有効なため置換されない）
- PDF変換には Microsoft Word（デスクトップ版）の COM オートメーションを使用する
  - メールのHTML本文をWordに読み込ませる方式（`Documents.Open`）は、メールの内容によってはWordの変換フィルタが極端に長時間応答しなくなることが確認されたため採用していない。代わりに `Documents.Add()` で新規文書を作成し、件名・差出人・宛先・CC・受信日時・本文・添付ファイル一覧をWordオブジェクトモデル（`Selection.TypeText` 等）で直接書き込んでから `ExportAsFixedFormat` でPDF化する
  - 元メールのHTMLの見た目（装飾）を再現することは目的とせず、文字情報を欠落させずに読みやすい文書として出力することを優先する。メール本文は原則として `MailItem.Body`（プレーンテキスト）を使用する
  - メール本文に含まれる外部画像・Web画像・外部CSS・Webフォント・外部リンク先コンテンツなどは取得しに行かない（閉域環境でもローカル処理だけで完結する）
  - `Word.Application` は実行全体（選択した全メールの処理）を通して1つのインスタンスだけを起動し、メールごとに起動・終了はしない（Word自体の起動コストは初回の1回のみ）
  - 画面には表示しない（`Visible = $false`、`DisplayAlerts = 0`、`AutomationSecurity = 3`）
  - メールごとの `Document` は作成したらその場で必ず `Close` する。`Word.Application` 自体の `Quit`／COM解放はスクリプト全体の終了処理（`finally`）でのみ行う
  - 1通のメールでPDF変換に失敗した場合、Word自体が引き続き使える状態であれば残りのメールの処理を継続する。COM接続が失われていると判断できた場合のみ、以降のメール処理を安全に打ち切る
  - 利用者が別途 Word を手作業で開いたままでも実行でき、そちらの Word を取得・終了することはない（mailexporter が自ら `New-Object -ComObject Word.Application` で生成したインスタンスのみを使用する）
  - Word がインストールされていない、または起動できない場合はエラーとして記録し、処理を中止する（他の変換方式への自動切り替えは行わない）
- PDF変換は `%TEMP%\MailExporter\{GUID}\` の短い一時フォルダ内だけで完結させ、完成したPDFのみを `.NET` のファイルAPIでメール保存フォルダへ移動する（件名等の長い/特殊文字を含むパスをWordへ直接渡さないため）
- 会議出席依頼や連絡先など、メール以外のアイテムを一緒に選択していた場合は処理対象外としてスキップされる（失敗としては数えない）
